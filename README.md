# Щиток 2

Независимое Android-приложение на основе «Щитка». Пакет `com.dd.shchitok2`, minSdk 24, targetSdk 34. Интерфейс: `assets/index.html` (WebView). Исходный проект `UltraPDF/shchitok` не используется для публикации и не изменяется.

Репозиторий: `https://github.com/dd77yy77-wq/shchitok-2`.

## Возможности версии 4.1

- Фото и схемы левого/правого щитков, подсветка автоматов, вкладки «Конвекторы» и «Септик» сохранены.
- При редактировании автомата задаются название, описание и категория. Устройство сразу появляется на вкладке «Устройства».
- Категорию можно выбрать из списка или создать прямо из формы автомата. Есть отдельная кнопка «Новая категория».
- Карточки устройств компактные; длинные названия переносятся без горизонтального переполнения.
- Кнопка удаления находится внутри формы редактирования устройства или категории. Удаление всегда требует подтверждения; отмена оставляет форму открытой и ничего не удаляет.
- При удалении категории её устройства перемещаются в «Без категории». При удалении связанного устройства пользовательская подпись автомата очищается, сам автомат остаётся.
- Кнопка «Выгрузить изменения» передаёт JSON с журналом операций и полным снимком данных.

## Данные и перенос изменений

Состояние «Щитка 2» хранится в WebView под ключом `shchitok2.state.v1`. Обновления поверх той же подписи сохраняют его. Android изолирует данные разных пакетов, поэтому локальные правки старого пакета `com.dd.shchitok` автоматически недоступны новому приложению.

Для включения присланного файла в новый выпуск:

```bash
python tools/apply_changes.py shchitok2-changes.json
```

Команда проверяет формат, объединяет операции по их уникальным `id` и обновляет `assets/release-ops.json` и `assets/release-ops.js`. На каждом телефоне операция применяется не более одного раза. Собственные более поздние правки пользователя не перезаписываются более старой операцией выпуска.

## Обновления через GitHub

При запуске приложение читает только:

`https://raw.githubusercontent.com/dd77yy77-wq/shchitok-2/main/version.json`

Если `code` больше установленного, оно скачивает `Shchitok2.apk` из той же директории и предлагает установить обновление. Для нового выпуска необходимо увеличить `code`, обновить `name`/`notes` и заменить APK.

## Сборка без Android SDK

Нужны JDK и Python 3 с пакетами `Pillow` и `cryptography`.

1. `tools/setup_dx.sh` собирает dx (class → dex) из исходников AOSP.
2. Ключ `keys/shchitok2.p12` создаётся один раз командой `python tools/make_signing_key.py`. Существующий ключ скрипт не заменяет.
3. `python build.py <versionCode> <versionName> Shchitok2.apk`.
4. Проверить ZIP, подпись v1/v2 и интерфейс. Нельзя использовать лямбды: старый dx их не поддерживает.

`build.py` собирает манифест, ресурсы, иконку, ZIP и подпись v1+v2. Классы Android берутся из `stubs/`.

## Структура

- `assets/` — интерфейс, общее состояние (`devices.js`), операции выпусков, фотографии.
- `src/`, `stubs/`, `tools/`, `build.py` — Android-оболочка и сборщик.
- `sources/` — исходные материалы пользователя.
- `tests/` — вспомогательные проверки интерфейса.
- `tools/publish.sh` — сборка и публикация только в `dd77yy77-wq/shchitok-2`, с проверкой remote.

## Ключ подписи

`keys/shchitok2.p12` исключён из Git через `.gitignore`. Без этого же ключа последующие обновления не установятся поверх приложения. Не публикуйте ключ и храните отдельную резервную копию.
