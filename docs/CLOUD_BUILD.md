# Облачная сборка Щитка 86

GitHub Actions собирает APK на временном сервере GitHub. После однократной настройки секретов включённый домашний компьютер для сборки и публикации не нужен. Этот сценарий относится только к репозиторию `dd77yy77-wq/shchitok-2`.

## Однократная настройка

Откройте `https://github.com/dd77yy77-wq/shchitok-2/settings/secrets/actions` и создайте два репозиторных секрета через **New repository secret**:

1. `SHCHITOK2_KEY_BASE64` — содержимое локального `keys/shchitok2.p12`, целиком преобразованное в Base64.
2. `SHCHITOK2_KEY_PASSWORD` — текущий пароль этого PKCS12-хранилища.

Значения нельзя отправлять в чат, issues, коммиты или архивы исходников. Если Base64 копировали через буфер обмена, очистите буфер после вставки. GitHub больше не показывает сохранённые значения; при ошибке секрет можно заменить новым значением.

Workflow открывает ключ только во временной папке runner-а и перед сборкой сверяет SHA-256 сертификата с сертификатом опубликованного приложения. Другой или повреждённый ключ останавливает выпуск. Сам ключ в APK не включается.

## Как выпускается новая версия

1. В коммит в `main` включаются изменения приложения и обновлённый `release-request.json`.
2. В запросе указываются `application: com.dd.shchitok2`, новый `code`, `name` и `notes`. Для обновления на телефонах `code` должен быть больше опубликованного.
3. Изменение `release-request.json` запускает workflow автоматически. Его также можно запустить вручную на вкладке **Actions**.
4. GitHub собирает APK, проверяет ZIP, интерфейс внутри пакета, пакет/версию и подписи v1/v2, сохраняет APK как артефакт проверки.
5. Только после успешных проверок workflow коммитит `Shchitok2.apk` и `version.json` в `main`. Номер новой версии телефоны видят лишь вместе с готовым APK.

Не редактируйте `version.json` вручную для обычного облачного выпуска: его обновляет workflow из запроса. При совпадающем `code` разрешена контрольная пересборка только с тем же `name`. Откат на меньший `code` запрещён.

Первый запрос настроен на контрольную сборку уже выпущенной версии 4.1 (code 29): это позволяет проверить облачную цепочку, не отправляя пользователям ложное обновление.
