# Восстановление проекта «Щиток 2»

Пакет `com.dd.shchitok2`, minSdk 24, targetSdk 34. Интерфейс — `assets/index.html` + `assets/devices.js` (WebView).

## Основные пути

- Репозиторий: `github.com/dd77yy77-wq/shchitok-2` (публичный).
- Исходники: `assets/`, `src/`, `stubs/`, `tools/`, `build.py`, `sources/`, `tests/`.
- Релиз для обновления: `Shchitok2.apk` + `version.json` в корне ветки `main`.
- Канал старого «Щитка» (`UltraPDF/shchitok`) не изменять.

## Ключ подписи

Локальный файл: `keys/shchitok2.p12`; пароль хранилища `android`; alias `shchitok2`.
SHA-256 сертификата: `B9:0E:1B:89:BF:DC:A5:8C:5A:E3:7E:38:67:0B:3B:32:71:8F:A6:20:3F:59:59:0C:47:A2:7D:D1:21:3C:07:06`.

Ключ не входит в Git и в архив исходников. Для обновлений поверх уже установленного «Щитка 2» использовать только его. При потере ключа потребуется новая подпись и переустановка приложения, поэтому нужна отдельная резервная копия ключа.

## Сборка

1. Нужны JDK и Python 3 с `Pillow` и `cryptography`.
2. Запустить `tools/setup_dx.sh`; при другом расположении dx задать `DXCP`.
3. Выполнить `python build.py <code> <name> Shchitok2.apk` из корня проекта.
4. Проверить `zipfile.testzip`, `apkbuild.v2_verify`, `jarsigner -verify` и интерфейс в Chromium/Playwright.
5. Не использовать лямбды в Java: только анонимные классы для совместимости с dx.

## Перенос файла пользователя в выпуск

1. Получить экспортированный `shchitok2-changes-*.json`.
2. Выполнить `python tools/apply_changes.py <файл>`.
3. Проверить, что новые операции появились в `assets/release-ops.json`, а повторный запуск даёт `0` новых операций.
4. Прогнать сценарии добавления/переименования/удаления и применения операций в чистом профиле.
5. Увеличить `versionCode`, собрать и подписать APK, затем опубликовать в новый репозиторий.

## Правила проекта

Русский интерфейс; старый «Щиток» не изменять; не выдавать старый APK за текущую сборку; сохранять исходники нового проекта на GitHub после каждого проверенного выпуска.
